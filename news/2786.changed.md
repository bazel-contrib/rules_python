(pypi) The dependencies between the PyPI packages now use the extras from the
wheel `METADATA`, e.g. if `foo` requires `bar[socks]`, then `@pypi//foo`
depends on `@pypi//bar:[socks]` instead of `@pypi//bar`. Previously such extras
were ignored. If the lock file of a hub does not request the extra, the build
fails with a message asking to add it, e.g. by compiling the requirements with
`--no-strip-extras`. This does not apply when there is no hub, e.g. with a
vendored `requirements.bzl`, where the dependencies use the `pkg` targets,
which include the extras from the lock file, as before. The `whl` targets no longer include the wheels of the
dependencies of the extras. A member of `experimental_requirement_cycles`
without extras, e.g. `foo`, is now only the package without extras, so the
cycles that go through `foo[bar]` need `foo[bar]` as a member. The same
distribution that is requested with different extras on different platforms
now uses a single whl repository. The `@pypi//foo` targets still include the
extras requested in the lock file. An extra that the package does not provide
is still ignored, but a warning is now printed like `pip` does, e.g.
`WARNING: foo 1.0 does not provide the extra 'nope'`
([#2786](https://github.com/bazel-contrib/rules_python/issues/2786)).
