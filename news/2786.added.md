(pypi) The hub repositories now have a `[]` target for each package without
any extras and an `[extra]` target for each extra used in the lock file, e.g.
`@pypi//google_api_core:[grpc]`, in both bzlmod and `WORKSPACE`. The
`requirement` macro accepts a single extra, e.g.
`requirement("google-api-core[grpc]")`, and the new `requirements` macro
returns a list of labels for any number of packages and extras, e.g.
`requirements("google-api-core[async_rest,grpc]", "numpy")`. The whl
repositories now create the targets for every extra that the package provides
and the requested extras are no longer passed to them, so changing the
requested extras does not refetch them. The dependencies use the extras from
the wheel `METADATA` and the build fails with a helpful message if an extra is
missing in the lock file. The `whl` targets no longer include the dependencies
of the extras. The members of `experimental_requirement_cycles` can now be the
extras of the packages, e.g. `foo[bar]`. See
[the docs](https://rules-python.readthedocs.io/en/latest/pypi/use.html#extras)
([#2786](https://github.com/bazel-contrib/rules_python/issues/2786),
[#4168](https://github.com/bazel-contrib/rules_python/issues/4168)).
